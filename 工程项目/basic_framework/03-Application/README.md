# Application 层总览

Application 把控制来源转成机器人动作，并组织各个 Module。设计目标是四个应用平行运行，通过 Message Center 交换结构体消息。

## 应用

| 应用 | 职责 | 当前状态 |
|---|---|---|
| RobotCMD | 控制源解析、模式仲裁、急停、发布命令 | 已启用 |
| Chassis | 坐标转换、麦轮解算、底盘电机目标 | 已启用 |
| Gimbal | Yaw/Pitch 闭环和姿态反馈 | 入口被注释 |
| Shoot | 摩擦轮、拨盘、舱盖控制 | 入口被注释且未完成 |

## 运行顺序

`RobotTask()` 当前按固定顺序调用：

```text
RobotCMDTask()
→ GimbalTask()（注释）
→ ShootTask()（注释）
→ ChassisTask()
```

在单板模式下，CMD 先发布本周期命令，Chassis 随后立刻读取，因此控制延迟很小。反馈则通常在下一周期被 CMD 读取。

## 开发规则

- 应用间通过话题交换数据，不直接访问其他应用的内部变量；
- 共享命令/反馈类型放在 `robot_def.h`；
- 硬件实例属于拥有它的应用，不要重复注册同一外设 ID；
- 安全停止应覆盖所有执行机构，并考虑通信离线和非法模式。

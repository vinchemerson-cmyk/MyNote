# Message Center

## 目的

隔离 Application 之间的数据依赖。发布者和订阅者只通过话题名及数据结构约定通信，不直接包含对方实例。

## 接口

```c
Publisher_t *PubRegister(char *name, uint8_t data_len);
Subscriber_t *SubRegister(char *name, uint8_t data_len);
uint8_t PubPushMessage(Publisher_t *pub, void *data);
uint8_t SubGetMessage(Subscriber_t *sub, void *data);
```

## 内部结构

- 所有话题组成 Publisher 单链表；
- 每个话题拥有订阅者单链表；
- 每个订阅者有独立消息队列；
- 当前 `QUEUE_SIZE = 1`。

因此它更接近“最新值邮箱”：订阅者没有及时读取时，旧消息会被新消息覆盖。

## 注册顺序

可以先订阅后发布。`SubRegister()` 内部会先查找或创建话题，再把新订阅者挂到话题链表。相同话题的数据长度不一致时会打印错误并死循环。

## 当前话题

```text
chassis_cmd  / chassis_feed
gimbal_cmd   / gimbal_feed
shoot_cmd    / shoot_feed
```

数据类型在 `robot_def.h` 定义。

## 限制

- 最多 12 个话题，话题名最多 32 字符；
- 长度使用 `uint8_t`；
- 初始化阶段动态分配内存；
- 没有锁或临界区，多任务同时读写时存在竞争风险；
- `PubPushMessage()` 当前固定返回 1，并不真实表示推送的订阅者数量。

当前 CMD/Chassis/Gimbal/Shoot 在同一个 Robot Task 中顺序调用，主要路径的竞争较少；新增其他任务访问话题时要重新评估线程安全。

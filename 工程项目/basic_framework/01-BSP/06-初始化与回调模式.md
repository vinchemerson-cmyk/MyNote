# BSP 初始化、回调任务和使用模式

## BSPInit

`bsp_init.h` 中的 `BSPInit()` 只初始化所有程序必需的基础设施：

```c
DWT_Init(168);
BSPLogInit();
```

CAN、UART、SPI 等实例型 BSP 采用“首次注册时启动硬件服务”，没有模块注册就不额外启动。

## 父指针回调

典型配置：

```c
config.can_module_callback = DecodeDevice;
config.id = device_instance;
device_instance->can = CANRegister(&config);
```

接收时 BSP 把自己的 `CANInstance *` 传给 `DecodeDevice()`；Module 再通过 `can->id` 找回真正的设备实例。这解决了底层不能包含上层头文件的问题。

## 中断内应该做什么

适合：

- 读取硬件缓冲区；
- 复制一帧短数据；
- 更新少量状态；
- 喂 Daemon；
- 唤醒任务。

不适合：

- 长协议解析；
- 复杂矩阵运算；
- 阻塞发送；
- 普通延时；
- 大量日志。

## CreateCallbackTask

`bsp_tools` 可以创建等待 CMSIS-RTOS signal 的回调任务。中断只发送信号，复杂回调在任务上下文执行。

```text
中断 → osSignalSet → CallbackTaskBase 被唤醒 → 执行 Module 回调 → 再次等待
```

最多管理 32 个 signal。当前实现创建任务后会先执行一次回调再等待信号，使用时应确认这是否符合模块期望。

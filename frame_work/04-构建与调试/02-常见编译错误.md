# 常见编译错误

## 大量错误先看第一条

C/C++ 编译经常发生级联错误。头文件开头失败后，后面所有类型和宏都会显示未定义。应先处理日志中第一个真实错误，再重新构建。

## cmsis_os.h 编码问题

本项目恢复后的两个文件曾是 UTF-16BE：

```text
Middlewares/Third_Party/FreeRTOS/Source/CMSIS_RTOS/cmsis_os.h
Middlewares/Third_Party/FreeRTOS/Source/CMSIS_RTOS/cmsis_os.c
```

典型报错：

```text
stray '\376' in program
stray '\377' in program
null character(s) ignored
unknown type name 'osThreadId'
```

应把两个文件“转换并保存”为 UTF-8，而不是仅用 UTF-8 重新加载。之后重新加载 CMake。

## unused-variable 变成 error

因为启用了 `-Werror`，以下警告会终止构建：

```text
error: 'xxx' defined but not used [-Werror=unused-variable]
```

优先处理方式：删除死变量、恢复其真实用途，或只在相应条件编译分支中声明。不要为通过构建随意写无意义的读取。

当前遇到过：

- `power_control.c` 的 `chassis_power`；
- 新版 `bmi088.c` 的 `whoami_check`；
- 新版 `bmi088.c` 的 `bmi088_daemon_instance`。

## 链接错误 multiple definition

通常是把函数或全局变量定义放在头文件，然后被多个 `.c` 包含。正确模式：

```c
// xxx.h
extern int value;
void Function(void);

// xxx.c
int value;
void Function(void) { ... }
```

`robot_task.h` 当前就包含实现，如果未来被第二个 `.c` 包含可能触发此问题。

## undefined reference

表示声明可见但链接阶段找不到实现。检查：

- `.c` 是否加入 CMake；
- 函数是否被条件编译排除；
- 声明和定义的名称/参数是否一致；
- 静态库路径和链接顺序；
- 是否误加 `static`。

## IDE 标红但编译通过

检查 CLion 是否加载 `cmake-build-debug/compile_commands.json`、ARM GCC 工具链、正确的宏和 include path。头文件单独分析时也可能缺少只由包含顺序提供的间接依赖。

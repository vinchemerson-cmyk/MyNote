# 裁判系统与 UI

## 文件分工

- `referee_protocol.h`：比赛协议的数据结构、命令 ID、UI 图形类型；
- `crc_ref`：裁判系统指定 CRC8/CRC16；
- `rm_referee`：UART 接收、校验和按 CmdID 解包；
- `referee_UI`：图形、字符、删除和批量刷新封包；
- `referee_task`：UI 初始化、状态变化检测和周期刷新；
- `referee_vt*`：图传链路/自定义控制器相关通信；
- `referee_custom`：机器人与自定义控制器交互数据。

## 接收链

```text
UART6 Receive-to-idle DMA
→ RefereeRxCallback
→ DaemonReload
→ JudgeReadData
→ SOF 0xA5 + CRC8 + CRC16
→ 根据 CmdID memcpy 到 referee_info_t 对应字段
```

同一 DMA 缓冲区可能含多帧，解析函数会递归处理后续 `0xA5` 帧。

## 公开入口

```c
referee_info_t *RefereeInit(UART_HandleTypeDef *uart);
void RefereeSend(uint8_t *data, uint16_t len);
referee_info_t *UITaskInit(UART_HandleTypeDef *uart, Referee_Interactive_info_t *ui);
void MyUIInit(void);
void UITask(void);
```

`RefereeSend()` 使用 DMA 发送后固定 `osDelay(34)`，限制发送速率并避免任务连续占用链路。

## UI

UI 初始化会等待机器人 ID 非零，确定己方机器人和客户端 ID，然后创建准线、状态文字和功率条。周期任务只在状态变化时使用 Change 操作更新。

## 当前重要问题

- `UITask()` 每次调用 `RobotModeTest()`，会自动修改 Chassis/Gimbal/Shoot 等 UI 状态；这是测试代码，上场前应移除或关闭；
- 协议版本会随赛季变化，应使用当年官方协议核对结构体和 CmdID；
- 大量结构体依赖 `pack(1)` 和小端布局；
- 在 UART 接收回调中直接解析长包，可能增加中断执行时间；
- UI 发送要遵守裁判系统带宽和频率限制。
